# 写作规则

本文件是 selfPromotion 内容工作室写稿的唯一规则来源（2026-10-23 从 selfPromotion 仓库的 AGENTS.md 第 1、2、3、5、7 节，`shuorenhua` 的「本项目写作口径」，以及 `argmap` skill 移植过来）。出图规则在 ARGMAP.md。

## 一、形态

- **每条 = 一张论证图 + 按内容量写的正文。** 素材有多少要点就写多少，通常 200–1,500 字，不凑字数也不压字数。不发长翻译，不发 X Article，不拆 thread。
- **唯一的硬约束是不枝蔓**：一句只做一件事；同一句里不叠第二个破折号插入语；不嵌套括号；一句里不并列三项以上。
- **开头不放元信息**：「出处：…」「素材：…」、英文原标题行都不放；来源一律放在首条回复里。推荐语已永久停写，不写那两行公式化开场。
- **正文里不放任何链接**：带站外链接的帖子会被 X 降权。原文链接放进**首条回复**，帖子发出后紧跟着发在它下面。
- **正文末尾**：一句「原文链接在评论区」，再一行话题标签，2–3 个，例如 `#评测 #Agent #LLM`。
- **首条回复**：`原文：<URL>`；几条素材就每条一行，写成「原文：」后换行逐行列出。
- 我们自己的判断用「我的判断：」引出，和原文的事实分开。

## 二、溯源

- **转发、转述类素材**（「某某说了什么」、curator 总结、引用别人观点的推）不直接翻译或转述推文本身：追到源头（原视频、原文、论文、GitHub repo），通读源内容并核对口径。找不到源头，或源头抓不到正文，就不写，并告诉读者为什么。
- **先读完原文再写。** 只读摘要写出来的就是三行没有实质内容的介绍。
- **零幻觉**：不编数字、比较、引用。正文和图里的每个数字都要能在原文里找到；条件和限定（「在某条件下」「可能」「平均」）跟着数字一起保留，不能写成更强的判断。
- 作者举的假设例子要说明是假设，不能写成实测。

## 三、切口

- 实操类、有代码、有具体步骤的素材最值得写；理论、观点类次之。
- **产品发布**：公告本身（「我们发布了 X 1.1」）没有可迁移的内容。只有当发布改变了品类格局、并且有第三方反应（平台封禁、记者调查、安全事件、竞品被迫跟进）时才写，而且切口必须是机制或产品形态，不复述公告。
- 厂商官博的分步教程、客户案例：只有给出机制或数字时才写，写的就是那个机制和那组数字。
- 每篇都要回答一个读者的问题：这能帮读者学会怎么用 AI 吗？回答不了，就告诉读者这条不适合写，别硬写。

## 四、按体裁写

- **单篇**：一条素材，一张图，一篇正文。
- **主题串烧**：几条素材回答**同一个读者问题**；把几条互不相干的新闻拼成一篇的大杂烩不做。门槛：
  1. 至少 3 条。
  2. 每条有自己的具体发现（一个数字或一个机制），单拿出来也站得住；凑数的边缘条目不进。
  3. 每条照常溯源、通读原文。
  4. 图只用 `compare`（几个对象放在同一组维度下比）或 `tree`（几项并列），不用 `fishbone` 或 `flow`：几条之间的共同点是我们归纳的，不是作者写明的。表格各格出自各篇原文，底部结论卡写明是我们的判断。
  5. 首条回复里每条一行原文链接。
  - 不够格时直接告诉读者，建议改成单篇或换素材，不硬串。
- **工具推荐**：说清它是什么、解决什么问题、怎么用或内部怎么运转。图按 ARGMAP.md 的规则 1 在 `steps`、`system`、`compare` 里选。
- **引用转发**：正文是我们对被引推文的补充和判断，不复述那条推文。需要被引推文的 URL，最好是作者本人发的那条。找不到时请读者给，或者建议改成单篇。

## 五、说人话

先过这几条，再交稿：

- **开头两句先交代三件事：这是什么、它解决什么问题、跟什么有关。** 钩子可以锋利，但不能靠隐藏主语和问题制造张力。外行测试：把第一句单独发给一个不做这行的人，他能不能说出「这在讲哪一类东西」；说不出就是没交代领域。
  - 反例：「Cohere 的 Rerank 5 没有只交一个更高榜单分数，它改了两件事」：不知道 Rerank 是什么、属于哪条流水线。
  - 正例：「RAG 里最容易被拍脑袋定下的数字是 top-k：检索回几篇文档塞给模型。Cohere 的 Rerank 5 改的就是这个常数。」
  - 隐晦只允许发生在论证上，不允许发生在主语与问题上。
- **先把「发生了什么」说清，再给结论。**
- **删掉叙述者。** 不写「我扫了一遍全网」「我把它整理如下」「更硬的一层」「时间线很实」「结果不是小幅改善」。叙述痕迹和替读者下的判断一起删，只留材料与判断本身。
- **删掉学术体面。** 词数、作者名单、文献编号、前作名与 arXiv 编号，对读者是零信息量的装饰。必要的溯源放首条回复的链接。
- **每篇要有一个读者的现实锚点**：论述落到读者正在付的钱、承担的风险或体感的变化上，不在材料的内部逻辑里打转。
- **只留判断所需的最小事实。** 读者要的是「它是什么、达到多少、代价多大、哪里会坏、意味着什么」。实现细节只在能改变这几个判断时才留。检验：删掉这一段，读者对这件事的判断会不会变？不变就删。
- **读者拿到的是判断，还是仪表盘？** 引用数、Hacker News 讨论数、自动摘要服务名单这类舆情统计整节删掉。
- **结尾用后果断言收，不用清单收。** 不说「缺了 A、B、C」，说「缺了 A、B、C 会怎样」。
- **交稿前逐句扫一遍**：同一句里两个以上破折号、「不是 X 而是 Y」句式、排比三连、意义拔高、宣传腔、万能展望结尾。扫到就改。
- **毛边是手迹**：口语、不工整的对仗不必修平。改之前问：改完以后，说话的人还在吗？

## 六、正文不能有 Markdown

X 不渲染 Markdown，`# 标题`、`**加粗**`、`- 列表`、`| 表格`、`> 引用`、代码围栏都会原样显示成符号。正文只用纯文本：中文标点、数字编号（1. 2.）、`·` 开头的行、直接贴的 URL、缩进的代码示例，段落之间空一行。`save_draft` 会检查，有 Markdown 的稿子进不了待发布。
